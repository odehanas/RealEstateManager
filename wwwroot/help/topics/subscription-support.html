Subscription

System Setup ▸ Subscription

Shows the company's current subscription state, its expiry date and the days remaining. New companies start on a 15-day trial. To extend, enter the activation code supplied by your provider and select Activate. The days are added to whichever is later - today or your current end date - so renewing early never loses time. The code is recorded against your name.

  • Before it ends, an orange notice appears at the top of every screen: in the last 5 days of the trial and the last 14 days of a paid subscription.
  • When it expires, the processing menus are withdrawn until it is renewed. No data is lost.
  • If access is suspended by your provider - for example over a payment - the same happens before the end date. Contact your provider: access returns as soon as they reactivate the company or you enter a new activation code.

Audit Logs

System Setup ▸ Audit Logs — system administrators only.

Records who did what and when across the application. Filter by user, date range, action or entity to investigate a change. Combined with Journal Inquiry, this gives a complete evidence trail: the audit log shows the user action, the journal shows its accounting consequence.

Help

System Setup ▸ Help

The Help Center: every help topic, grouped the same way as the menus, with a search box. The Help button on any screen opens just that screen's topic. System Setup ▸ User Manual opens the complete manual as one printable document, with a PDF to download.

Feedback

System Setup ▸ Send Feedback

Submit a problem report or an improvement request. Include the screen name, what you did, what you expected and what happened, plus any document number involved — that is usually enough to resolve an issue without further correspondence. Administrators review submissions under System Setup ▸ Feedback Review.

Database Updates

System Setup ▸ Database Updates — the platform owner only.

Each new version of the application brings its own database changes as numbered scripts, and applies any it has not applied before when the site starts. Nobody needs to run SQL in the hosting console any more: deploying the new version is enough. Every script is applied at most once, all or nothing, and the record of what has been applied is kept in the database itself.

  • Safety. A script runs as a single unit: if any of its statements fails, none of it is kept. The application never removes tables, columns or data on its own - a script that would do so is refused unless it is explicitly marked as reviewed.
  • If an update fails, the site still opens. The page shows the script and statement that failed and the database's own error message, and no later scripts are applied. Send the page to your developer; the next deployment tries again.
  • First start after this feature arrived. Scripts 01 to 21 had already been run by hand. The application recognised them from the tables they created and recorded them as Already in place without running them again.
