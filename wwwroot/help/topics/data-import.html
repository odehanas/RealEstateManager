When a customer moves to RealEstateManager, their records come over from the previous system through one Excel file: download the template, fill it, upload it. The file is checked cell by cell and row by row, and imported only when everything in it is right — then all of it at once.

What can be imported

SheetWhat it holdsPermission needed
PropertiesBuildings and plots, owned or managed, with their registration details.Create & Edit Master Data
UnitsThe units of each property: floor, use, area, asking rent.Create & Edit Master Data
TenantsIndividuals, businesses and government tenants, with IDs, TRN and opening balance.Create & Edit Master Data
VendorsSuppliers, with VAT registration and opening balance.Create & Edit Master Data
LeasesRunning contracts: unit, tenant, dates, rent, billing and deposit.Manage Leases
EmployeesStaff with documents, salary and bank details.Manage HR

The template has only the sheets you may import. A file with rows on a sheet you may not import is refused.

Step by step

  1. Open Master Data ▸ Import Data and select Download template (.xlsx). It comes in the language you are working in; either language's file can be uploaded.
  2. Fill one row per record from row 2. Start with the Instructions sheet; pointing at a header shows what the column takes. Columns marked * are required.
  3. Give every record your own reference in its ref column, unique on that sheet — the old system's number works well. The other sheets use it: a unit gives its Property ref, a contract its Unit ref and Tenant ref, an employee the property they work for. A record already in the system can be named by its code instead, e.g. OWN-R-0001.
  4. Select Check the file and upload it. Every problem is listed with its sheet, row and column; correct them in your file and upload it again.
  5. When nothing is wrong, the screen shows how many records of each kind will be created. Select Import.
  6. Select Download the result file: your file with a System code column holding each record's new code. Keep it; later files can name these records by those codes.

Format rules apply on top: an email address must be valid, a TRN has 15 digits, a UAE IBAN 23 characters starting with AE, a MOHRE person code 14 digits, a bank routing code 9 digits, a country code two letters.

The same rules as the entry screens

  • Codes are generated by the system, exactly as when a record is entered by hand.
  • A tenant's Emirates ID, passport, TRN or trade licence, a vendor's TRN or licence, a property's name or title deed and an employee's Emirates ID must not already be in the system — or on another row of the file. Uploading the same file twice is therefore refused the second time.
  • A managed property needs its owner's name; a VAT registered vendor its TRN; a limited employment contract its end date; a salary paid by WPS or bank transfer an IBAN.
  • A contract's end date must be after its start, its billing every 1, 2, 3, 4, 6 or 12 months, and its unit free for its dates — against running contracts and against the other contracts of the file.
  • A department named on the Employees sheet that is not in the system yet is created; the check says which.
Contracts arrive as drafts

Importing a contract creates no invoice and no revenue. Open Master Data ▸ Leases, review each imported contract (its old number is in the notes) and activate it, as for any new contract. The unit becomes Occupied then.

All of it, or nothing

The import runs as one transaction: if anything fails part-way, nothing is kept. And the file is checked again at the moment of import, so records entered by someone else since the check are taken into account.

A sheet takes up to 5,000 rows and a file up to 10 MB; split a larger migration into several files, importing properties and units before the contracts that use them. Opening balances of tenants and vendors are recorded on their records; the ledger side is entered in Opening Balances.
