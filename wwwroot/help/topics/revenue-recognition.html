This screen turns billed rent into earned revenue, one month at a time. It is the mechanism that keeps the Profit & Loss faithful to the period rather than to the billing cycle.

How the schedule is built

When a lease is saved, one planned entry is created for the last day of every month in the lease term, each for one-twelfth of the annual rent. Every entry starts with status Planned.

Running the recognition

  1. Open System Setup ▸ Revenue Recognition. Planned and posted entries are listed.
  2. Enter the cut-off date — normally the last day of the month you are closing.
  3. Select Post All Due Up To Selected Date, or Post on a single entry. A journal is created for every planned entry dated on or before the cut-off, oldest first.
  4. Post those journals from Journal Inquiry. Each entry's status then changes to Posted.
These buttons create draft journals

They reach the Profit & Loss only once posted from Operations ▸ Journal Inquiry — filter the Source Type to RevenueRecognitionSchedule and use Post All Drafts. See Draft, Post & Reset to Draft.

Make this the first task of every month-end

Run revenue recognition before printing the Profit & Loss. If you skip it, revenue for the month is missing and the deferred-income balance is overstated by the same amount. Running it late is safe: each entry keeps its own month-end date, so the figures land in the correct period.

Reading the deferred balance

At any date, the balance on 21200 Advances from Customers is the rent you have billed but not yet earned. It should equal the sum of all planned (unposted) recognition entries for invoices already posted. This is a useful monthly reconciliation.
